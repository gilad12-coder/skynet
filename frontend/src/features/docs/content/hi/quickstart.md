यह पेज बताता है कि लगभग दस मिनट में अपना पहला रन कैसे शुरू करें। आप साइन इन करते हैं, एक छोटा डेटासेट अपलोड करते हैं, विज़ार्ड के चार चरण भरते हैं, और रन शुरू करते हैं। यह उदाहरण एक ऐसे प्रॉम्प्ट को बेहतर बनाता है जो सपोर्ट संदेशों को लेबल में बाँटता है।

## शुरू करने से पहले

आपको चाहिए:

- एक Skynet खाता।
- एक CSV, JSON या Excel फ़ाइल (`.csv`, `.json`, `.xlsx` या `.xls`)। हर पंक्ति एक केस है।
- एक या ज़्यादा इनपुट कॉलम, उदाहरण के लिए `message`।
- एक अपेक्षित-आउटपुट कॉलम, उदाहरण के लिए `label`।

> [!TIP]
> कम से कम 5 पंक्तियाँ इस्तेमाल करें। 5 से कम जोड़ों पर Skynet कोई परीक्षण सेट नहीं रखता, इसलिए अंतिम स्कोर उन्हीं केसों से आता है जिन्हें ऑप्टिमाइज़र ने इस्तेमाल किया।

## 1. साइन इन करें

Skynet में साइन इन करें। फिर `/submit` पर सबमिट पेज खोलें।

> [!NOTE]
> यह पेज **स्टैंडर्ड** स्तर के लेबल इस्तेमाल करता है। **गाइडेड** स्तर सरल लेबल इस्तेमाल करता है, ऑप्टिमाइज़र चरण छोड़ देता है, और आपके लिए **Auto** चुनता है। स्तर को सेटिंग्स में बदलें।

## 2. टास्क

पहला चरण **टास्क** है। यह पूछता है "आप क्या ऑप्टिमाइज़ करना चाहते हैं?"

1. **लक्ष्य** में लिखें कि अच्छा परिणाम क्या है। सरल शब्द इस्तेमाल करें, उदाहरण के लिए "हर सपोर्ट संदेश को billing, bug या other में बाँटें।"
2. वैकल्पिक: **पृष्ठभूमि** में ऐसा संदर्भ जोड़ें जो ऑप्टिमाइज़र की मदद करे।
3. **आर्टिफ़ैक्ट प्रकार** में **प्रॉम्प्ट** चुनें।
4. **शुरुआती संस्करण** में अपना मौजूदा प्रॉम्प्ट पेस्ट करें।

## 3. इनपुट

दूसरा चरण **इनपुट** है।

1. **CSV, JSON या Excel फ़ाइल अपलोड करें** चुनें, या सहेजा हुआ डेटासेट इस्तेमाल करने के लिए **लाइब्रेरी से चुनें** चुनें।
2. **डेटा कैसे पढ़ा जाए** के नीचे हर कॉलम को एक भूमिका दें:
   - **इनपुट**: रन कोड को यह कॉलम मिलता है।
   - **आउटपुट**: अपेक्षित मान। मेट्रिक को यह मिलता है।
   - **छोड़ें**: Skynet इस कॉलम का इस्तेमाल नहीं करता।
3. विभाजन के लिए **अनुशंसा का उपयोग करें** रहने दें। ज़्यादातर डेटासेट के लिए विभाजन 70% प्रशिक्षण, 15% मान्यकरण और 15% परीक्षण होता है।

पूरे नियमों के लिए [डेटासेट और विभाजन](/docs/concepts/datasets) पढ़ें।

## 4. ऑप्टिमाइज़र

तीसरा चरण **ऑप्टिमाइज़र** ("ऑप्टिमाइज़र, मॉडल और बजट") है।

- ऑप्टिमाइज़र को **Auto** पर रहने दें।
- एक **रिफ़्लेक्शन मॉडल** चुनें। ऑप्टिमाइज़र नए संस्करण लिखने के लिए इसका इस्तेमाल करता है। यह मॉडल ज़रूरी है।
- वैकल्पिक: एक **टास्क मॉडल** चुनें। आपका रन कोड इसका इस्तेमाल करता है।
- **बजट** के नीचे **अधिकतम स्कोरर रन** को उसके डिफ़ॉल्ट मान 200 पर रहने दें।

कोई खास इंजन चुनने के लिए [इंजन](/docs/concepts/engines) पढ़ें।

## 5. मेट्रिक और रन

आखिरी चरण **मेट्रिक और रन** ("कोड और मेट्रिक") है। आप दो फ़ाइलें लिखते हैं।

```python tab="run.py"
from skynet import llm


def run(artifact, input):
    return llm(artifact, input=input["message"])
```

```python tab="metric.py"
def score(input, output, expected=None):
    want = expected["label"].strip().lower()
    got = str(output).strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`artifact` आपके प्रॉम्प्ट का मौजूदा संस्करण है। `input` में एक केस के इनपुट कॉलम होते हैं। `expected` में आउटपुट कॉलम होता है, उसके कॉलम नाम की कुंजी के साथ।

फिर **कॉन्ट्रैक्ट जाँच** के नीचे **जाँचें** चुनें। यह जाँच आपके कोड और आपके मेट्रिक को सैंडबॉक्स में 3 नमूना केसों पर चलाती है। यह इन चीज़ों को जाँचती है:

| जाँच                   | क्या विफल होता है                                                    |
| ---------------------- | ------------------------------------------------------------------- |
| रन कोड सिग्नेचर        | `run.py` में `run(artifact, input)` परिभाषित नहीं है                   |
| मेट्रिक सिग्नेचर       | `metric.py` में `score(input, output, expected=None)` परिभाषित नहीं है |
| मेट्रिक मॉडल           | मेट्रिक मॉडल इस्तेमाल करने लायक नहीं है                               |
| नमूनों पर रन कोड       | आपका रन कोड किसी नमूना केस पर एरर देता है                              |
| मेट्रिक का रिटर्न मान  | `score` एक मान्य स्कोर और फ़ीडबैक नहीं लौटाता                           |

> [!NOTE]
> कॉन्ट्रैक्ट जाँच पास होने के बाद ही आप रन शुरू कर सकते हैं।

## 6. शुरू करें और देखें

सारांश स्क्रीन पर "चलाने के लिए तैयार" दिखता है। इसके टैब हैं: सामान्य, डेटा, मॉडल, बजट और रिवॉर्ड। सेटअप जाँचें, फिर ऑप्टिमाइज़ेशन शुरू करें।

रन को देखने के लिए उसे अपनी ऑप्टिमाइज़ेशन सूची से खोलें। स्कोर और विजेता संस्करण को समझने के लिए [परिणाम](/docs/guides/results) पढ़ें।
