سرور MCP در Skynet به یک عامل هوش مصنوعی اجازه می‌دهد به جای شما از Skynet استفاده کند. Claude، ChatGPT، Codex، Cursor و دیگر کلاینت‌های MCP می‌توانند تنظیمات یک اجرا را بررسی کنند، اجراها را شروع کنند، آن‌ها را پیگیری کنند و متوقفشان کنند. شما اتصال را یک بار در مرورگر تأیید می‌کنید. عامل برای هر اجرا یک سقف هزینه تعیین می‌کند.

## نشانی سرور

همهٔ کلاینت‌ها از یک نشانی استفاده می‌کنند:

```text
https://mcp.skynetml.com/mcp
```

سرور از Streamable HTTP استفاده می‌کند. ورود از OAuth 2.1 استفاده می‌کند. لازم نیست توکن یا کلید API را در کلاینت کپی کنید.

## اتصال کلاینت

کلاینت خود را انتخاب کنید. گام‌های آن را دنبال کنید، سپس به [تأیید اتصال](#تأیید-اتصال) بروید.

## تأیید اتصال

اولین باری که عامل Skynet را فراخوانی می‌کند، مرورگر شما یک صفحهٔ Skynet را باز می‌کند.

1. اگر وارد Skynet نشده‌اید، وارد شوید.
2. صفحه را بخوانید. این صفحه نام عامل، سایتی که عامل به آن برمی‌گردد و حساب شما را نشان می‌دهد.
3. بخوانید عامل چه کارهایی می‌تواند انجام دهد:
   - اجراهای بهینه‌سازی شما و نتیجه‌های آن‌ها را ببیند.
   - اجراهای بهینه‌سازی را شروع و متوقف کند، با پرداخت از موجودی شما.
4. برای اتصال روی **Allow** کلیک کنید. برای توقف روی **Deny** کلیک کنید.

بعد از کلیک روی **Allow**، مرورگر به عامل برمی‌گردد. اکنون عامل می‌تواند ابزارهای زیر را فراخوانی کند.

> [!NOTE]
> عامل برای هر اجرا یک سقف هزینه تعیین می‌کند. عامل نمی‌تواند موجودی اضافه کند.

## ابزارها

| ابزار       | چه کاری انجام می‌دهد                                                                 | دسترسی |
| ----------- | ----------------------------------------------------------------------------------- | ------ |
| `check_run` | تنظیمات یک اجرا را بدون اجرای آن و بدون دریافت هزینه بررسی می‌کند. یک سقف هزینه پیشنهاد می‌دهد. | خواندن |
| `start_run` | یک اجرا را با یک سقف هزینه شروع می‌کند.                                             | نوشتن  |
| `get_run`   | وضعیت، هزینهٔ انجام‌شده و، وقتی اجرا تمام شود، نتیجه را برمی‌گرداند.                 | خواندن |
| `list_runs` | اجراهای شما را از جدیدترین فهرست می‌کند. می‌تواند بر اساس وضعیت فیلتر کند.           | خواندن |
| `stop_run`  | یک اجرا را متوقف می‌کند. فراخوانی دوم خطایی برمی‌گرداند که می‌گوید اجرا قبلاً تمام شده است. | نوشتن  |

دسترسی خواندن از دامنهٔ `runs:read` استفاده می‌کند. دسترسی نوشتن از دامنهٔ `runs:write` استفاده می‌کند.

هیچ ابزاری موجودی اضافه نمی‌کند، موجودی شما را تغییر نمی‌دهد و تنظیمات صورت‌حساب را تغییر نمی‌دهد.

## عامل چگونه یک بهینه‌سازی را اجرا می‌کند

1. عامل `check_run` را با تنظیمات اجرا فراخوانی می‌کند. Skynet بررسی‌های ایستا را اجرا می‌کند و این موارد را برمی‌گرداند:
   - نتیجهٔ هر بررسی.
   - کمترین سقف هزینه‌ای که اجرا می‌تواند با آن شروع شود.
   - یک سقف هزینهٔ پیشنهادی. این مقدار دست‌کم ۵٫۰۰ دلار است.
   - مدل‌هایی که قیمت شناخته‌شده‌ای ندارند.
   - مبلغی که اکنون می‌توانید هزینه کنید.
2. عامل `start_run` را با یک سقف هزینه (`max_cost_cents`، از ۱ تا ۱٬۰۰۰٬۰۰۰ سنت آمریکا) فراخوانی می‌کند. همچنین می‌تواند یک `idempotency_key` بفرستد تا تلاش دوباره اجرای دومی را شروع نکند.
3. اگر بررسی تنظیمات هنوز در حال اجرا باشد، `start_run` مقدارهای `in_progress` و `retry_after_seconds` را برمی‌گرداند. عامل بعد از آن زمان، `start_run` را دوباره با همان ورودی فراخوانی می‌کند.
4. عامل `get_run` را تا پایان اجرا فراخوانی می‌کند. وضعیت‌های نهایی `success`، `failed`، `cancelled` و `stopped` هستند.

> [!TIP]
> سقف هزینهٔ خود را در پرامپت به عامل بگویید، برای مثال «این پرامپت را بهینه کن. حداکثر ۱۰ دلار هزینه کن.» عامل سپس از همین سقف در `start_run` استفاده می‌کند.

اجرا وقتی به سقف هزینهٔ خود برسد متوقف می‌شود. برای اینکه بدانید Skynet چگونه هزینهٔ یک اجرا را دریافت می‌کند، [صورت‌حساب](/docs/concepts/billing) را بخوانید.

## امنیت

- هر کلاینت مجوز جداگانهٔ خود را می‌گیرد. کلاینت هرگز رمز عبور شما را نمی‌بیند.
- ورود از PKCE (S256) استفاده می‌کند. کلاینت خود را با ثبت پویای کلاینت (dynamic client registration) یا یک سند فراداده‌ی شناسهٔ کلاینت (client ID metadata document) ثبت می‌کند.
- توکن‌های دسترسی بعد از ۱ ساعت منقضی می‌شوند. کلاینت آن‌ها را با یک توکن تازه‌سازی (refresh token) تمدید می‌کند.
- توکن تازه‌سازی بعد از ۳۰ روز بدون استفاده منقضی می‌شود. هر مجوز حداکثر ۹۰ روز اعتبار دارد. سپس باید اتصال را دوباره تأیید کنید.
- هر توکن تازه‌سازی فقط یک بار کار می‌کند. اگر کسی دوباره از یک توکن تازه‌سازی قدیمی استفاده کند، Skynet مجوز را پایان می‌دهد.
- عامل فقط می‌تواند اجراهای خود شما را ببیند و تغییر دهد.

برای اینکه بدانید Skynet چگونه از حساب و داده‌های شما محافظت می‌کند، [امنیت](/docs/security) را بخوانید.

## قطع اتصال

برای قطع اتصال یک عامل، سرور Skynet را از کلاینت حذف کنید. بیشتر کلاینت‌ها سپس توکن‌های خود را باطل می‌کنند. اگر کلاینتی آن‌ها را باطل نکند، توکن تازه‌سازی آن بعد از ۳۰ روز بدون استفاده منقضی می‌شود.

## عیب‌یابی

| مشکل                                         | چه باید کرد                                                                 |
| -------------------------------------------- | --------------------------------------------------------------------------- |
| اتصال بلافاصله شکست می‌خورد                  | نشانی سرور را بررسی کنید. باید دقیقاً `https://mcp.skynetml.com/mcp` باشد.   |
| «This agent can't connect»                   | اتصال را دوباره از کلاینت شروع کنید.                                        |
| «Too many attempts»                          | چند دقیقه صبر کنید، سپس دوباره تلاش کنید.                                   |
| کلاینت مرورگری باز نمی‌کند                   | کلاینت را به‌روز کنید. کلاینت باید از سرورهای MCP راه دور با OAuth پشتیبانی کند. |
| `start_run` با خطای موجودی شکست می‌خورد      | در Skynet موجودی اضافه کنید، یا اجرا را با سقف هزینهٔ کمتری شروع کنید.       |
| ابزارها بعد از چند هفته کار نمی‌کنند         | مجوز منقضی شده است. سرور را حذف کنید و دوباره متصل شوید.                    |

برای دسترسی مستقیم HTTP بدون عامل، [API](/docs/api) را بخوانید.
