این صفحه نشان می‌دهد چگونه اولین اجرای خود را در حدود ده دقیقه شروع کنید. وارد حساب می‌شوید، یک مجموعه‌دادهٔ کوچک بارگذاری می‌کنید، چهار مرحلهٔ ویزارد را پر می‌کنید و اجرا را شروع می‌کنید. مثال این صفحه پرامپتی را بهتر می‌کند که پیام‌های پشتیبانی را در برچسب‌ها دسته‌بندی می‌کند.

## پیش از شروع

به این موارد نیاز دارید:

- یک حساب Skynet.
- یک فایل CSV، JSON یا Excel (`.csv`، `.json`، `.xlsx` یا `.xls`). هر ردیف یک مورد است.
- یک یا چند ستون ورودی، برای مثال `message`.
- یک ستون خروجی مورد انتظار، برای مثال `label`.

> [!TIP]
> دست‌کم ۵ ردیف استفاده کنید. با کمتر از ۵ جفت، Skynet مجموعهٔ آزمون نگه نمی‌دارد، پس امتیاز نهایی از موردهایی می‌آید که بهینه‌ساز از آن‌ها استفاده کرده است.

## ۱. ورود

وارد Skynet شوید. سپس صفحهٔ ارسال را در `/submit` باز کنید.

> [!NOTE]
> این صفحه از برچسب‌های سطح **استاندارد** استفاده می‌کند. سطح **راهنمایی‌شده** برچسب‌های ساده‌تری دارد، مرحلهٔ بهینه‌ساز را رد می‌کند و **Auto** را برای شما انتخاب می‌کند. سطح را در تنظیمات تغییر دهید.

## ۲. کار

مرحلهٔ اول **کار** است. این مرحله می‌پرسد «چه چیزی را می‌خواهید بهینه کنید؟»

1. در **هدف**، بنویسید نتیجهٔ خوب چیست. از کلمه‌های ساده استفاده کنید، برای مثال «هر پیام پشتیبانی را در یکی از دسته‌های صورت‌حساب، باگ یا سایر قرار بده.»
2. اختیاری: در **پیش‌زمینه**، زمینه‌ای اضافه کنید که به بهینه‌ساز کمک می‌کند.
3. در **نوع آرتیفکت**، **پرامپت** را انتخاب کنید.
4. در **نسخهٔ شروع**، پرامپت فعلی خود را بچسبانید.

## ۳. ورودی‌ها

مرحلهٔ دوم **ورودی‌ها** است.

1. **بارگذاری فایل CSV، JSON یا Excel** را انتخاب کنید، یا برای استفاده از یک مجموعه‌دادهٔ ذخیره‌شده **انتخاب از کتابخانه** را انتخاب کنید.
2. زیر **نحوهٔ خواندن داده**، به هر ستون یک نقش بدهید:
   - **ورودی**: کد اجرا این ستون را دریافت می‌کند.
   - **خروجی**: مقدار مورد انتظار. معیار آن را دریافت می‌کند.
   - **رد کردن**: Skynet از این ستون استفاده نمی‌کند.
3. برای تقسیم، **استفاده از پیشنهاد** را نگه دارید. برای بیشتر مجموعه‌داده‌ها، تقسیم ۷۰٪ آموزش، ۱۵٪ اعتبارسنجی و ۱۵٪ آزمون است.

برای قاعده‌های کامل، [مجموعه‌داده‌ها و تقسیم‌ها](/docs/concepts/datasets) را بخوانید.

## ۴. بهینه‌ساز

مرحلهٔ سوم **بهینه‌ساز** است («بهینه‌ساز، مدل‌ها و بودجه»).

- بهینه‌ساز را روی **Auto** نگه دارید.
- یک **مدل بازاندیشی** انتخاب کنید. بهینه‌ساز از آن برای نوشتن نسخه‌های جدید استفاده می‌کند. این مدل الزامی است.
- اختیاری: یک **مدل وظیفه** انتخاب کنید. کد اجرای شما از آن استفاده می‌کند.
- زیر **بودجه**، **حداکثر اجراهای امتیازدهنده** را روی مقدار پیش‌فرض ۲۰۰ نگه دارید.

برای انتخاب یک موتور مشخص، [موتورها](/docs/concepts/engines) را بخوانید.

## ۵. معیار و اجرا

مرحلهٔ آخر **معیار و اجرا** است («کد و معیار»). دو فایل می‌نویسید.

```python tab="run.py"
from skynet import llm


def run(artifact, input):
    return llm(artifact, input=input["message"])
```

```python tab="metric.py"
def score(input, output, expected=None):
    want = expected["label"].strip().lower()
    got = str(output).strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`artifact` نسخهٔ فعلی پرامپت شماست. `input` ستون‌های ورودی یک مورد را نگه می‌دارد. `expected` ستون خروجی را نگه می‌دارد، با نام ستون به‌عنوان کلید.

سپس زیر **بررسی قرارداد**، **بررسی** را انتخاب کنید. این بررسی کد و معیار شما را در محیط اجرا روی ۳ مورد نمونه اجرا می‌کند. این موارد را بررسی می‌کند:

| بررسی                    | چه چیزی شکست می‌خورد                                          |
| ------------------------ | ------------------------------------------------------------ |
| امضای کد اجرا            | `run.py` تابع `run(artifact, input)` را تعریف نمی‌کند          |
| امضای معیار              | `metric.py` تابع `score(input, output, expected=None)` را تعریف نمی‌کند |
| مدل معیار                | مدل معیار قابل استفاده نیست                                  |
| کد اجرا روی نمونه‌ها     | کد اجرای شما روی یک مورد نمونه خطا می‌دهد                     |
| مقدار بازگشتی معیار      | `score` امتیاز و بازخورد معتبر برنمی‌گرداند                    |

> [!NOTE]
> فقط بعد از قبولی در بررسی قرارداد می‌توانید اجرا را شروع کنید.

## ۶. شروع و پیگیری

صفحهٔ خلاصه «آماده‌ی اجرا» را نشان می‌دهد. زبانه‌های آن عمومی، داده‌ها، مدل‌ها، بودجه و پاداش هستند. تنظیمات را بررسی کنید، سپس بهینه‌سازی را شروع کنید.

برای پیگیری اجرا، آن را از فهرست بهینه‌سازی‌های خود باز کنید. برای فهمیدن امتیازها و نسخهٔ برنده، [نتیجه‌ها](/docs/guides/results) را بخوانید.

- بدانید یک اجرا چقدر هزینه دارد: [صورت‌حساب](/docs/concepts/billing).
