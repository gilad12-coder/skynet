Сервер MCP від Skynet дає змогу AI-агенту користуватися Skynet замість вас. Claude, ChatGPT, Codex, Cursor та інші клієнти MCP можуть перевіряти налаштування запуску, запускати оптимізації, стежити за ними й зупиняти їх. Ви один раз схвалюєте підключення у своєму браузері. Агент задає ліміт витрат для кожного запуску.

## URL-адреса сервера

Усі клієнти використовують ту саму URL-адресу:

```text
https://mcp.skynetml.com/mcp
```

Сервер використовує Streamable HTTP. Вхід використовує OAuth 2.1. Вам не потрібно копіювати токен або ключ API в клієнт.

## Підключення клієнта

Оберіть свій клієнт. Виконайте його кроки, а потім перейдіть до розділу [Схвалення підключення](#схвалення-підключення).

## Схвалення підключення

Коли агент уперше звертається до Skynet, ваш браузер відкриває сторінку Skynet.

1. Увійдіть у Skynet, якщо ви ще не ввійшли.
2. Прочитайте сторінку. Вона показує назву агента, сайт, на який він повертається, і ваш акаунт.
3. Прочитайте, що може робити агент:
   - Переглядати ваші запуски оптимізації та їхні результати.
   - Запускати й зупиняти оптимізації з оплатою з вашого балансу.
4. Натисніть **Allow**, щоб підключитися. Натисніть **Deny**, щоб скасувати.

Після того як ви натиснете **Allow**, браузер повернеться до агента. Тепер агент може викликати інструменти, описані нижче.

> [!NOTE]
> Агент задає ліміт витрат для кожного запуску. Поповнювати баланс він не може.

## Інструменти

| Інструмент  | Що робить                                                                                   | Доступ  |
| ----------- | ------------------------------------------------------------------------------------------- | ------- |
| `check_run` | Перевіряє налаштування запуску, не виконуючи його й не стягуючи з вас кошти. Пропонує ліміт витрат. | Читання |
| `start_run` | Створює запуск із лімітом витрат.                                                           | Запис   |
| `get_run`   | Повертає статус, витрати, а після завершення запуску — результат.                           | Читання |
| `list_runs` | Повертає список ваших запусків, від найновіших. Може фільтрувати за статусом.               | Читання |
| `stop_run`  | Зупиняє запуск. Повторний виклик повертає помилку, що запуск уже завершився.               | Запис   |

Доступ на читання використовує scope `runs:read`. Доступ на запис використовує scope `runs:write`.

Жоден інструмент не поповнює баланс, не змінює ваш баланс і не змінює налаштування оплати.

## Як агент виконує оптимізацію

1. Агент викликає `check_run` з налаштуваннями запуску. Skynet виконує статичні перевірки й повертає:
   - Результат кожної перевірки.
   - Найменший ліміт витрат, з яким можна почати запуск.
   - Рекомендований ліміт витрат. Він становить щонайменше $5.00.
   - Моделі, ціна яких невідома.
   - Суму, яку ви можете витратити зараз.
2. Агент викликає `start_run` з лімітом витрат (`max_cost_cents`, від 1 до 1 000 000 центів США). Він також може надіслати `idempotency_key`, щоб повторна спроба не створила другий запуск.
3. Якщо перевірка налаштувань ще триває, `start_run` повертає `in_progress` і `retry_after_seconds`. Після цього часу агент знову викликає `start_run` з тими самими вхідними даними.
4. Агент викликає `get_run`, доки запуск не завершиться. Підсумкові статуси: `success`, `failed`, `cancelled` і `stopped`.

> [!TIP]
> Вкажіть агенту свій ліміт витрат у промпті, наприклад: «Оптимізуй цей промпт. Витрать щонайбільше $10». Тоді агент використає цей ліміт у `start_run`.

Запуск зупиняється, коли досягає свого ліміту витрат. Як Skynet стягує оплату за запуск, описано в розділі [Бюджети й оплата](/docs/concepts/billing).

## Безпека

- Кожен клієнт отримує власний дозвіл (grant). Клієнт ніколи не бачить ваш пароль.
- Вхід використовує PKCE (S256). Клієнт реєструється через dynamic client registration або через client ID metadata document.
- Термін дії access token спливає через 1 годину. Клієнт оновлює їх за допомогою refresh token.
- Термін дії refresh token спливає після 30 днів без використання. Дозвіл діє щонайбільше 90 днів. Після цього ви знову схвалюєте підключення.
- Кожен refresh token працює лише один раз. Якщо хтось повторно використає старий refresh token, Skynet скасує дозвіл.
- Агент може бачити й змінювати лише ваші власні запуски.

Як Skynet захищає ваш акаунт і дані, описано в розділі [Безпека](/docs/security).

## Відключення

Щоб відключити агента, видаліть сервер Skynet із клієнта. Більшість клієнтів після цього відкликають свої токени. Якщо клієнт їх не відкликає, термін дії його refresh token спливає після 30 днів без використання.

## Усунення несправностей

| Проблема                                       | Що робити                                                                       |
| ---------------------------------------------- | ------------------------------------------------------------------------------- |
| Підключення одразу завершується помилкою       | Перевірте URL-адресу сервера. Вона має бути точно `https://mcp.skynetml.com/mcp`. |
| «This agent can't connect»                     | Почніть підключення знову з клієнта.                                            |
| «Too many attempts»                            | Зачекайте кілька хвилин і спробуйте ще раз.                                     |
| Клієнт не відкриває браузер                    | Оновіть клієнт. Він має підтримувати віддалені сервери MCP з OAuth.             |
| `start_run` завершується помилкою балансу      | Поповніть баланс у Skynet або почніть запуск із меншим лімітом витрат.          |
| Інструменти перестають працювати через кілька тижнів | Термін дії дозволу сплив. Видаліть сервер і підключіться знову.          |

Для прямого доступу через HTTP без агента прочитайте [API](/docs/api).
