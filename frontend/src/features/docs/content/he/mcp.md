שרת ה-MCP של Skynet מאפשר לסוכן AI להשתמש ב-Skynet בשבילך. ‏Claude,‏ ChatGPT,‏ Codex,‏ Cursor ולקוחות MCP אחרים יכולים לבדוק הגדרות של ריצה, להפעיל ריצות, לעקוב אחריהן ולעצור אותן. מאשרים את החיבור פעם אחת בדפדפן. הסוכן קובע תקרת הוצאה לכל ריצה.

## כתובת השרת

כל הלקוחות משתמשים באותה כתובת:

```text
https://mcp.skynetml.com/mcp
```

השרת משתמש ב-Streamable HTTP. ההתחברות משתמשת ב-OAuth 2.1. אין צורך להעתיק token או מפתח API ללקוח.

## חיבור הלקוח

בחר/י את הלקוח שלך. בצע/י את השלבים שלו, ואז עבור/עברי אל [אישור החיבור](#אישור-החיבור).

```skynet-mcp-clients

```

## אישור החיבור

בפעם הראשונה שהסוכן קורא ל-Skynet, הדפדפן פותח דף של Skynet.

1. התחבר/י ל-Skynet, אם עדיין לא התחברת.
2. קרא/י את הדף. הוא מציג את שם הסוכן, את האתר שהוא חוזר אליו ואת החשבון שלך.
3. קרא/י מה הסוכן יכול לעשות:
   - לראות את ריצות האופטימיזציה שלך ואת התוצאות שלהן.
   - להפעיל ולעצור ריצות אופטימיזציה, בתשלום מהיתרה שלך.
4. לחץ/י על **אישור** כדי להתחבר. לחץ/י על **דחייה** כדי לעצור.

אחרי הלחיצה על **אישור**, הדפדפן חוזר לסוכן. עכשיו הסוכן יכול לקרוא לכלים שבהמשך.

> [!NOTE]
> הסוכן קובע תקרת הוצאה לכל ריצה. הוא לא יכול להוסיף כסף.

## כלים

| כלי         | מה הוא עושה                                                          | גישה  |
| ----------- | -------------------------------------------------------------------- | ----- |
| `check_run` | בודק הגדרות של ריצה בלי להריץ אותה ובלי לחייב אותך. מציע תקרת הוצאה. | קריאה |
| `start_run` | מפעיל ריצה עם תקרת הוצאה.                                            | כתיבה |
| `get_run`   | מחזיר את הסטטוס, את ההוצאה, וכשהריצה מסתיימת, את התוצאה.             | קריאה |
| `list_runs` | מציג את הריצות שלך, מהחדשה לישנה. יכול לסנן לפי סטטוס.               | קריאה |
| `stop_run`  | עוצר ריצה. קריאה שנייה מחזירה שגיאה שאומרת שהריצה כבר הסתיימה.       | כתיבה |

גישת קריאה משתמשת ב-scope ‏`runs:read`. גישת כתיבה משתמשת ב-scope ‏`runs:write`.

אף כלי לא מוסיף כסף, לא משנה את היתרה שלך ולא משנה הגדרות חיוב.

## איך סוכן מריץ אופטימיזציה

1. הסוכן קורא ל-`check_run` עם הגדרות הריצה. ‏Skynet מריץ את הבדיקות הסטטיות ומחזיר:
   - את התוצאה של כל בדיקה.
   - את תקרת ההוצאה הנמוכה ביותר שהריצה יכולה להתחיל איתה.
   - תקרת הוצאה מוצעת. היא לפחות ‎$5.00.
   - את המודלים שאין להם מחיר ידוע.
   - את הסכום שאפשר להוציא עכשיו.
2. הסוכן קורא ל-`start_run` עם תקרת הוצאה (`max_cost_cents`, בין 1 ל-1,000,000 סנט אמריקאי). הוא יכול גם לשלוח `idempotency_key`, כדי שניסיון חוזר לא יפעיל ריצה שנייה.
3. אם בדיקת ההגדרות עדיין רצה, `start_run` מחזיר `in_progress` ו-`retry_after_seconds`. הסוכן קורא שוב ל-`start_run` עם אותו קלט אחרי הזמן הזה.
4. הסוכן קורא ל-`get_run` עד שהריצה מסתיימת. הסטטוסים הסופיים הם `success`,‏ `failed`,‏ `cancelled` ו-`stopped`.

> [!TIP]
> כתוב/י לסוכן את תקרת ההוצאה שלך בפרומפט, למשל "שפר את הפרומפט הזה. אל תוציא יותר מ-‎$10." הסוכן ישתמש אז בתקרה הזו ב-`start_run`.

הריצה נעצרת כשהיא מגיעה לתקרת ההוצאה שלה. קרא/י את [חיוב](/docs/concepts/billing) כדי להבין איך Skynet מחייב על ריצה.

## אבטחה

- כל לקוח מקבל הרשאה משלו. הלקוח אף פעם לא רואה את הסיסמה שלך.
- ההתחברות משתמשת ב-PKCE ‏(S256). הלקוח רושם את עצמו בעזרת dynamic client registration או בעזרת client ID metadata document.
- תוקף ה-access tokens פג אחרי שעה אחת. הלקוח מחדש אותם בעזרת refresh token.
- תוקף refresh token פג אחרי 30 ימים בלי שימוש. הרשאה נמשכת לכל היותר 90 ימים. אחר כך מאשרים את החיבור שוב.
- כל refresh token עובד פעם אחת בלבד. אם מישהו משתמש שוב ב-refresh token ישן, Skynet מבטל את ההרשאה.
- הסוכן יכול לראות ולשנות רק את הריצות שלך.

קרא/י את [אבטחה](/docs/security) כדי להבין איך Skynet מגן על החשבון ועל הנתונים שלך.

## ניתוק

כדי לנתק סוכן, הסר/הסירי את שרת Skynet מהלקוח. רוב הלקוחות מבטלים אז את ה-tokens שלהם. אם לקוח לא מבטל אותם, תוקף ה-refresh token שלו פג אחרי 30 ימים בלי שימוש.
