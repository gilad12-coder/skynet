העמוד הזה מראה איך להפעיל את הריצה הראשונה שלך בכעשר דקות. מתחברים, מעלים דאטאסט קטן, ממלאים את ארבעת השלבים של האשף ומפעילים את הריצה. הדוגמה משפרת פרומפט שממיין הודעות תמיכה לתוויות.

## לפני שמתחילים

צריך:

- חשבון Skynet.
- קובץ CSV,‏ JSON או Excel ‏(`.csv`, `.json`, `.xlsx` או `.xls`). כל שורה היא מקרה אחד.
- עמודת קלט אחת או יותר, למשל `message`.
- עמודת פלט צפוי אחת, למשל `label`.

> [!TIP]
> יש להשתמש בלפחות 5 שורות. עם פחות מ-5 זוגות, Skynet לא שומר קבוצת בדיקה, ולכן הציון הסופי מגיע ממקרים שהאופטימייזר השתמש בהם.

## 1. התחברות

התחבר/י ל-Skynet. אחר כך פתח/י את דף ההגשה ב-`/submit`.

> [!NOTE]
> העמוד הזה משתמש בתוויות של הרמה **רגיל**. הרמה **מודרך** משתמשת בתוויות פשוטות יותר, מדלגת על שלב האופטימייזר ובוחרת **Auto** בשבילך. אפשר לשנות את הרמה בהגדרות.

## 2. משימה

השלב הראשון הוא **משימה**. הוא שואל "מה תרצו לייעל?"

1. בשדה **מטרה**, כתוב/י מהי תוצאה טובה. השתמש/י במילים פשוטות, למשל "מיין כל הודעת תמיכה ל-billing,‏ bug או other."
2. אופציונלי: בשדה **רקע**, הוסף/הוסיפי הקשר שעוזר לאופטימייזר.
3. בשדה **סוג התוצר**, בחר/י **פרומפט**.
4. בשדה **גרסת התחלה**, הדבק/י את הפרומפט הנוכחי שלך.

## 3. קלטים

השלב השני הוא **קלטים**.

1. בחר/י **העלו קובץ CSV,‏ JSON או Excel**, או **בחירה מהספרייה** כדי להשתמש בדאטאסט שמור.
2. תחת **איך לקרוא את הנתונים**, תן/תני לכל עמודה תפקיד:
   - **קלט**: קוד ההרצה מקבל את העמודה הזו.
   - **פלט**: הערך הצפוי. פונקציית המדידה (Metric) מקבלת אותו.
   - **דלג/י**: Skynet לא משתמש בעמודה הזו.
3. השאר/י **לפי ההמלצה** לחלוקה. ברוב הדאטאסטים החלוקה היא 70% אימון, 15% אימות ו-15% בדיקה.

קרא/י את [דאטאסטים וחלוקה](/docs/concepts/datasets) לכל הכללים.

## 4. אופטימייזר

השלב השלישי הוא **מאפטם** ("אופטימייזר, מודלים ותקציב").

- השאר/י את האופטימייזר על **Auto**.
- בחר/י **מודל רפלקציה** (מודל האופטימיזציה). האופטימייזר משתמש בו כדי לכתוב גרסאות חדשות. המודל הזה הוא חובה.
- אופציונלי: בחר/י **מודל המשימה**. קוד ההרצה שלך משתמש בו.
- תחת **תקציב**, השאר/י את **מקסימום הרצות ניקוד** על ברירת המחדל, 200.

קרא/י את [מנועים](/docs/concepts/engines) כדי לבחור מנוע ספציפי.

## 5. מדד והרצה

השלב האחרון הוא **מדד והרצה** ("קוד ומדד"). כותבים שני קבצים.

```python tab="run.py"
from skynet import llm


def run(artifact, input):
    return llm(artifact, input=input["message"])
```

```python tab="metric.py"
def score(input, output, expected=None):
    want = expected["label"].strip().lower()
    got = str(output).strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`artifact` היא הגרסה הנוכחית של הפרומפט שלך. `input` מכיל את עמודות הקלט של מקרה אחד. `expected` מכיל את עמודת הפלט, עם שם העמודה כמפתח.

אחר כך בחר/י **בדיקה** תחת **בדיקת חוזה**. הבדיקה מריצה את הקוד ואת פונקציית המדידה שלך ב-sandbox על 3 מקרים לדוגמה. היא בודקת:

| בדיקה                | מה נכשל                                                    |
| -------------------- | ---------------------------------------------------------- |
| חתימת קוד ההרצה      | `run.py` לא מגדיר `run(artifact, input)`                   |
| חתימת המדד           | `metric.py` לא מגדיר `score(input, output, expected=None)` |
| מודל המדד            | אי אפשר להשתמש במודל המדד                                  |
| הרצת הקוד על דוגמאות | קוד ההרצה זורק שגיאה על מקרה לדוגמה                        |
| ערך ההחזרה של המדד   | `score` לא מחזיר ציון ומשוב תקינים                         |

> [!NOTE]
> אפשר להפעיל את הריצה רק אחרי שבדיקת החוזה עוברת.

## 6. הפעלה ומעקב

מסך הסיכום מציג "מוכן להרצה". הלשוניות שלו הן כללי, נתונים, מודלים, תקציב ותגמול. בדוק/בדקי את ההגדרות, ואז הפעל/י את האופטימיזציה.

פתח/י את הריצה מרשימת האופטימיזציות שלך כדי לעקוב אחריה. קרא/י את [תוצאות](/docs/guides/results) כדי להבין את הציונים ואת הגרסה המנצחת.
