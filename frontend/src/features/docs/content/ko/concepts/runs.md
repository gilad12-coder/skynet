실행은 한 번의 최적화입니다. 실행에는 상태, 지출 한도, 저장된 버전 세트가 있습니다. 이 페이지는 실행 상태, 실행에서 할 수 있는 작업, 실행이 멈추는 이유를 설명합니다.

## 실행 상태

모든 실행은 다음 상태 중 하나를 가집니다.

| 상태         | 의미                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| `pending`    | 실행이 대기열에 있습니다.                                                  |
| `validating` | 최적화가 시작되기 전에 Skynet이 설정을 검사합니다.                         |
| `running`    | 옵티마이저가 새 버전을 제안하고 채점합니다.                                |
| `success`    | 실행이 끝났습니다. 최고 버전이 저장되었습니다.                             |
| `failed`     | 오류로 실행이 멈췄습니다.                                                  |
| `cancelled`  | 사용자가 실행을 취소했습니다.                                              |
| `paused`     | 실행이 체크포인트에서 멈췄습니다. 다시 시작할 수 있습니다.                 |
| `stopped`    | 실행이 예산에 도달해 멈췄습니다. 찾은 최고 버전을 유지합니다.              |

`success`, `failed`, `cancelled`, `stopped`, `paused`는 종료 상태입니다. 옵티마이저는 종료 상태의 실행에서 작업하지 않습니다. `paused`는 다시 시작하기 위해 존재하는 유일한 종료 상태입니다.

## 작업

실행 페이지는 현재 상태와 내 역할에 해당하는 작업을 보여 줍니다. API에도 같은 작업이 있습니다.

| 작업            | 사용할 수 있는 경우                                                                                       | 하는 일                                                                 |
| --------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **일시 중지**   | 실행이 진행 중이고 저장된 체크포인트가 있습니다.                                                          | 체크포인트에서 실행을 멈춥니다. 상태가 `paused`로 바뀝니다.             |
| **취소**        | 실행이 `pending`, `validating` 또는 `running` 상태입니다.                                                 | 실행을 중지합니다. 취소는 되돌릴 수 없습니다.                           |
| **다시 시작**   | 실행이 `failed`, `cancelled`, `paused` 상태이거나 예산에 도달해 `stopped` 상태이고, 저장된 체크포인트가 있습니다. | 마지막 체크포인트에서 같은 실행을 이어 갑니다. 실행 ID가 유지됩니다.     |
| **복제**        | 실행을 볼 수 있으면 언제든지.                                                                             | 구성 사본으로 제출 마법사를 엽니다.                                     |
| **삭제**        | 실행이 종료 상태입니다. 소유자만 가능합니다.                                                              | 실행과 모든 데이터를 영구적으로 삭제합니다.                             |

API에는 `failed` 또는 `cancelled` 상태인 실행에 대한 작업이 두 가지 더 있습니다.

- **재시도**는 같은 구성으로 새 실행을 시작합니다. 새 실행은 새 ID를 받습니다.
- **처음부터 실행**은 같은 실행을 처음부터 다시 시작합니다. 실행 ID가 유지됩니다.

> [!NOTE]
> 재시도, 처음부터 실행, API 복제는 자체 지출 한도가 있는 실행을 거부합니다. 새 실행을 시작하기 전에 제출 마법사에서 구성을 열고 새 예산을 설정하세요. 실행 페이지의 **복제** 버튼은 이 작업을 대신 해 줍니다.

API 복제는 요청 한 번에 1~5개의 사본을 만들 수 있습니다. 각 사본은 실행 제한에 포함됩니다. [제한](/docs/limits)을 참고하세요.

### 누가 작업을 할 수 있나요

실행에 대한 내 역할에 따라 보이는 작업이 달라집니다.

- **소유자**는 모든 작업을 하고, 공유를 관리하고, 실행을 삭제할 수 있습니다.
- **편집자**는 실행을 일시 중지, 취소, 다시 시작, 재시도할 수 있고, 지출 한도를 올릴 수 있습니다.
- **뷰어**는 실행을 열고 복제할 수 있습니다.

역할에 대한 자세한 내용은 [공유 및 게시](/docs/guides/sharing)를 읽어 보세요.

## 실행이 멈추는 방식

실행은 네 가지 이유 중 하나로 멈춥니다.

### 완료

옵티마이저가 작업을 마칩니다. 상태가 `success`로 바뀝니다. Skynet은 최고 버전을 저장하고 최종 테스트를 실행합니다. [결과 읽기](/docs/guides/results)를 읽어 보세요.

### 예산

실행에는 시작 전 비용 추정치가 없습니다. 지출 한도가 실행이 사용할 수 있는 예산입니다. Skynet은 실행이 진행되는 동안 각 채점기 실행의 실제 비용을 측정합니다.

1. Skynet은 정산된 채점기 실행이 10회가 될 때까지 기다립니다. 그 전에는 호출 한 번의 비용 편차가 너무 커서 사용할 수 없습니다.
2. Skynet은 지금까지의 평균 비용으로 다음 반복의 가격을 정합니다. 이후 반복은 대개 비용이 더 들기 때문에 가격에 1.5를 곱합니다.
3. 남은 예산으로 다음 반복 비용을 낼 수 없으면 Skynet은 새 작업을 받지 않습니다. 옵티마이저는 다음 유료 호출에서 멈춥니다.

그러면 실행은 `stopped` 상태가 되고 중지 이유는 `budget_reached`가 됩니다. 실행 페이지에 **예산 한도 도달** 알림이 표시됩니다. 알림은 Skynet이 어떤 버전을 저장했는지 알려 줍니다.

- 평가된 최고 버전.
- 더 나은 버전을 찾지 못했다면, 평가된 시작 버전.
- 후보가 평가를 마치기 전에 예산이 소진되었다면, 버전 없음. 입력과 로그는 저장된 상태로 남습니다.

계속하려면 알림에서 **한도 올리고 계속**을 사용하세요. Skynet은 마지막 체크포인트에서 실행을 다시 시작합니다.

> [!TIP]
> **한도 없음**으로 설정한 실행은 끝날 때까지 계정 잔액을 사용합니다. 잔액이 바닥나면 실행은 멈추고 지금까지의 결과를 유지합니다. 이때 알림에는 **계정 잔액 소진**이 표시됩니다. 충전한 다음 실행을 다시 시작하세요.

일부 이전 실행은 중지 이유 `budget_projected`로 일시 중지되었습니다. 이런 실행도 같은 방법으로 다시 시작할 수 있습니다.

### 실패

오류로 실행이 멈춥니다. 상태가 `failed`로 바뀝니다. **로그** 탭에서 무슨 일이 있었는지 볼 수 있습니다. 실행에 저장된 체크포인트가 있으면 다시 시작할 수 있습니다. 재시도할 수도 있습니다.

워커가 작업을 실행하는 도중에 멈추면 Skynet은 작업을 복구하고 다시 시도합니다. 3번 시도한 후에는 Skynet이 작업을 실패로 표시합니다. 실패나 취소 후의 다시 시작도 시도 횟수에 포함됩니다. 일시 중지나 예산 중지 후의 다시 시작은 포함되지 않습니다.

### 취소

사용자가 실행을 취소합니다. 상태가 `cancelled`로 바뀝니다. 취소는 되돌릴 수 없습니다. 나중에 저장된 체크포인트에서 실행을 다시 시작하거나 재시도할 수 있습니다.
