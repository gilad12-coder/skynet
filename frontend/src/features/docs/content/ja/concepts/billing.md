Skynet は前払いの残高を使います。残高に資金を追加します。各実行には支出上限があり、Skynet は実行の実際の使用量を残高に請求します。このページでは、残高、実行予算、確保額、手数料、独自のプロバイダーキーについて説明します。

> [!NOTE]
> このページの数値は現在の既定値です。アプリには最新の値が表示されます。残高、チャージ手数料、取引履歴を確認するには、**設定 → 請求** を開いてください。

## 残高

残高の単位は米ドルです。Skynet はセント単位で管理します。

既定では、Skynet は無料の初期残高を付与しません。最初の有料の実行を開始する前に、資金を追加してください。

資金は **設定 → 請求** で追加します。固定額を選ぶか、カスタム額を入力できます。

| チャージ   | 残高に追加される金額         |
| ---------- | ---------------------------- |
| 固定額     | $5、$20、または $50          |
| カスタム   | $5〜$1,000 の任意の金額      |

選んだ金額がそのまま残高に入ります。チャージ手数料はその金額に上乗せされます。手数料については下記をご覧ください。

**設定 → 使用状況** には、支出した金額が表示されます。**設定 → 請求** の取引履歴には、チャージと実行の請求が一覧表示されます。

## 実行予算

各実行には支出上限があります。上限は、その実行が支出できる最大額です。設定と最適化の両方が含まれます。

実行には、開始前のコスト見積もりがありません。上限まで支出し、予算に達すると停止し、最良のバージョンを保持します。Skynet がいつ停止するかをどう判断するかは、[実行](/docs/concepts/runs) をお読みください。

上限は、送信ウィザードの **予算** 画面の **支出上限** フィールドで設定します。

- **上限を設定** が既定のモードです。上限は $5 から始まります。実行の開始に $5 より多く必要な場合は、その金額から始まります。
- **上限なし** を選ぶと、実行は完了するまで残高から引き落とします。実行が一時停止することはありません。残高が尽きると、実行は停止し、それまでに作成したものを保持します。

### 開始に必要な金額

ウィザードには **開始に必要な額** が表示されます。この金額は次の合計です。

- 実行が最初のモデル呼び出しの前に開くサンドボックスの保留額
- 最初のモデル呼び出しのための余裕分。余裕分は $1、または選択したモデルの単一呼び出しで最も高価なもののコストのほうが大きい場合はその金額です。

上限がこの金額を下回っている場合、ウィザードでは先に進めません。残高がこの金額を下回っている場合も同様です。続行するには、上限を引き上げるか、資金を追加してください。

> [!TIP]
> 実行が予算に達して停止したら、実行ページの **上限を引き上げて続行** を使います。実行は最後のチェックポイントから続行します。

## 確保額

有料の処理を行う前に、Skynet は実行の上限の一部を確保します。処理が精算されると、Skynet は確保を解除し、実際のコストだけを請求します。

予算にすでにアクティビティがある場合、ウィザードの **支出上限** カードにその台帳が表示されます。

| ラベル             | 意味                                                                       |
| ------------------ | -------------------------------------------------------------------------- |
| **この上限の残り** | 上限のうち残っている部分。                                                 |
| **これまでの支出** | 精算済みのコスト。                                                         |
| **予約済み**       | 進行中の処理のために保留されている金額。処理が精算されると Skynet が解除します。 |

## 手数料

Skynet には、プロバイダーのコストに加えて 3 つの料金があります。

| 料金                               | 現在の既定値                                 | 適用対象                                                  |
| ---------------------------------- | -------------------------------------------- | --------------------------------------------------------- |
| チャージ手数料                     | 金額の 12.5% + $0.35                         | 各チャージ                                                |
| 使用量マークアップ                 | プロバイダーのコスト × 1.15（コスト + 15%）  | Skynet のキーによるモデル呼び出しと、サンドボックスの計算 |
| 独自キーのプラットフォーム手数料   | モデルコストの 5%                            | 独自のプロバイダーキーによるモデル呼び出し                |

### チャージ手数料

Skynet は、割合の部分を 1 セント単位で切り上げ、$0.35 を加算します。たとえば、$20 のチャージの手数料は $2.85 です。チャージ画面には、支払いの前に手数料が表示されます。

### 使用量マークアップ

Skynet は、プロバイダーのコストに使用量マークアップを掛けます。マークアップは、Skynet が支払うモデル呼び出しと、サンドボックスの計算に適用されます。確保額、開始に必要な金額、アプリ内のモデル価格には、すでにマークアップが含まれています。

Skynet は、モデル呼び出しのプロバイダーのコストを次の順序で求めます。

1. OpenRouter がその呼び出しについて報告するコスト。
2. そのモデルの OpenRouter の最新価格表。
3. LiteLLM の価格表。
4. 入力トークン 100 万あたり $15、出力トークン 100 万あたり $75 という高めのフォールバック料金。この料金により、Skynet が不明なモデルをコストより安く請求することはありません。

## 独自のプロバイダーキー (BYOK)

モデル呼び出しを、独自のプロバイダーキーで実行できます。キーは **設定 → プロバイダー** で追加します。OpenRouter の場合は、**OpenRouter で続行** も使えます。

モデル呼び出しにあなたのキーを使う場合:

- プロバイダーが、モデルのトークンをあなたのキーに請求します。
- Skynet は、モデルコストの 5% のプラットフォーム手数料を残高から請求します。この手数料には、使用量マークアップは加算されません。
- 実行の支出上限の対象は、プラットフォーム手数料とサンドボックスの使用量だけです。

外部のスコアラーや MCP プロバイダーの料金は、そのプロバイダーに直接支払われます。実行の支出上限には含まれません。

## サンドボックスの使用量

実行コードとメトリクスはサンドボックスで実行されます。Skynet はサンドボックスの計算を計測します。

1. サンドボックスが起動する前に、Skynet は実行の上限から一定額を確保します。
2. サンドボックスが終了すると、Skynet はサンドボックスのプロバイダーが報告する最終的な使用量を請求します。
3. サンドボックスの計算には、使用量マークアップが適用されます。

サンドボックスの計算は、モデル呼び出しに独自のキーを使う場合でも、実行の支出上限に含まれます。

## プラン

プランは Free と Pro の 2 つです。Pro では、同時実行数やストレージなど、一部の制限が引き上げられます。Pro の更新に失敗した場合、アカウントは 7 日間 Pro の制限を維持します。その後は、支払いが成功するまで Free の制限が適用されます。[制限](/docs/limits) をご覧ください。

## プラットフォームの保護機能

- アシスタントとのチャットなど、対話的なモデルのターンを開始するには、少なくとも $0.05 の残高が必要です。
- ウィザードアシスタントは無料です。各アカウントは、UTC の 1 日あたり 50 回までウィザードアシスタントのターンを開始できます。
