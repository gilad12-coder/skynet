توضّح هذه الصفحة كيف تبدأ أول تشغيل لك في نحو عشر دقائق. تسجّل الدخول، وترفع مجموعة بيانات صغيرة، وتملأ خطوات المعالج الأربع، ثم تبدأ التشغيل. يحسّن المثال موجّهًا يصنّف رسائل الدعم إلى تسميات.

## قبل أن تبدأ

تحتاج إلى:

- حساب Skynet.
- ملف CSV أو JSON أو Excel (`.csv` أو `.json` أو `.xlsx` أو `.xls`). كل صف هو حالة واحدة.
- عمود إدخال واحد أو أكثر، مثل `message`.
- عمود واحد للمخرج المتوقع، مثل `label`.

> [!TIP]
> استخدم 5 صفوف على الأقل. مع أقل من 5 أزواج، لا يحتفظ Skynet بمجموعة اختبار، فتأتي الدرجة النهائية من حالات استخدمها المُحسِّن.

## 1. تسجيل الدخول

سجّل الدخول إلى Skynet. ثم افتح صفحة الإرسال على `/submit`.

> [!NOTE]
> تستخدم هذه الصفحة تسميات المستوى **قياسي**. يستخدم المستوى **موجَّه** تسميات أبسط، ويتخطّى خطوة المُحسِّن، ويختار **Auto** نيابةً عنك. غيّر المستوى من الإعدادات.

## 2. المهمة

الخطوة الأولى هي **المهمة**. تسألك "ما الذي تريد تحسينه؟"

1. في **الهدف**، اكتب ما هي النتيجة الجيدة. استخدم كلمات بسيطة، مثل "صنّف كل رسالة دعم إلى فوترة أو خلل أو أخرى."
2. اختياري: في **الخلفية**، أضف سياقًا يساعد المُحسِّن.
3. في **نوع العنصر**، اختر **موجّه**.
4. في **نسخة البداية**، الصق موجّهك الحالي.

## 3. المدخلات

الخطوة الثانية هي **المُدخلات**.

1. اختر **ارفع ملف CSV أو JSON أو Excel**، أو **اختيار من المكتبة** لاستخدام مجموعة بيانات محفوظة.
2. تحت **كيفية قراءة البيانات**، أعطِ كل عمود دورًا:
   - **المُدخل**: يتلقى كود التشغيل هذا العمود.
   - **المُخرج**: القيمة المتوقعة. يتلقاها المقياس.
   - **تخطٍّ**: لا يستخدم Skynet هذا العمود.
3. أبقِ **استخدم التوصية** للتقسيم. في معظم مجموعات البيانات يكون التقسيم 70% للتدريب و15% للتحقق و15% للاختبار.

اقرأ [مجموعات البيانات والتقسيمات](/docs/concepts/datasets) للاطلاع على القواعد الكاملة.

## 4. المحسن

الخطوة الثالثة هي **المُحسِّن** ("المُحسِّن والنماذج والميزانية").

- أبقِ المُحسِّن على **Auto**.
- اختر **نموذج التأمل**. يستخدمه المُحسِّن لكتابة نسخ جديدة. هذا النموذج مطلوب.
- اختياري: اختر **نموذج المهمة**. يستخدمه كود التشغيل الخاص بك.
- تحت **الميزانية**، أبقِ **الحد الأقصى لتشغيلات المُقيِّم** على قيمته الافتراضية 200.

اقرأ [المحرّكات](/docs/concepts/engines) لاختيار محرّك معيّن.

## 5. المقياس والتشغيل

الخطوة الأخيرة هي **المقياس والتشغيل** ("الكود والمقياس"). تكتب ملفين.

```python tab="run.py"
from skynet import llm


def run(artifact, input):
    return llm(artifact, input=input["message"])
```

```python tab="metric.py"
def score(input, output, expected=None):
    want = expected["label"].strip().lower()
    got = str(output).strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`artifact` هو النسخة الحالية من موجّهك. يحمل `input` أعمدة الإدخال لحالة واحدة. ويحمل `expected` عمود الإخراج، مفهرسًا باسم العمود.

ثم اختر **فحص** تحت **فحص العقد**. يشغّل الفحص الكود والمقياس في البيئة المعزولة على 3 حالات نموذجية. ويتحقق مما يلي:

| الفحص                         | ما الذي يفشل                                                        |
| ----------------------------- | ------------------------------------------------------------------- |
| توقيع كود التشغيل             | لا يعرّف `run.py` الدالة `run(artifact, input)`                     |
| توقيع المقياس                 | لا يعرّف `metric.py` الدالة `score(input, output, expected=None)`   |
| نموذج المقياس                 | نموذج المقياس غير قابل للاستخدام                                    |
| كود التشغيل على النماذج       | يُطلق كود التشغيل خطأً على حالة نموذجية                             |
| قيمة إرجاع المقياس            | لا تُرجع `score` درجة وملاحظات صالحة                                |

> [!NOTE]
> لا يمكنك بدء التشغيل إلا بعد نجاح فحص العقد.

## 6. البدء والمتابعة

تعرض شاشة الملخص "جاهز للتشغيل". علاماتها هي عام والبيانات والنماذج والميزانية والمكافأة. راجع الإعداد، ثم ابدأ التحسين.

افتح التشغيل من قائمة عمليات التحسين لمتابعته. اقرأ [النتائج](/docs/guides/results) لفهم الدرجات والنسخة الفائزة.
